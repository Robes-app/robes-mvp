# Robes Platform — Claude Code Guide

**Current milestone: M1 (M0 complete 2026-09-24).** Plans index: `docs/plans/README.md`.

This folder is the rebuild of Robes as a secure, scalable platform: Next.js web (`app/`), Expo app (`mobile/`), Lambda workers (`workers/`), AWS CDK (`infra/`), Postgres migrations (`db/`), local services (`docker-compose.yml`) and shared packages (`packages/*`). The platform is the product: app.byrobes.com and the iOS app (beta.byrobes.com was retired on 23 Nov 2026). The legacy app at the repo root (`server.js`, `public/`, root `supabase/*.sql`) now serves only www.byrobes.com and is **reference only** — never import from it, never edit it from platform work (legacy fixes follow `docs/plans/2026-09-24-p0-legacy-hotfixes.md` on their own branch).

## Start of every session
1. Read `docs/SPEC.md` (§0 reading order, §4 decisions, §8 milestones, §9 open decisions).
2. Open the plan for the current milestone. If only a brief exists in `docs/plans/roadmap.md`, expand it with `superpowers:writing-plans` into `docs/plans/<date>-m<N>-<name>.md` first.
3. Execute with `superpowers:executing-plans` (or `subagent-driven-development` for independent tasks). Commit after each task.

## Working with the owner
The founder isn't an engineer: they may run you from this folder and ask in plain words (`docs/HANDOVER.md`).
- Explain what you'll do and what changed in plain language; run the commands yourself.
- Work on a branch and open a PR into `beta`; never push to `main`/`beta`, deploy production, change Vercel/AWS/Supabase settings or rotate secrets unless explicitly asked. Releasing (the sync, workers, TestFlight) follows `docs/runbooks/ios-release.md`.
- If a request would break a rule in `docs/api-security.md`, say so plainly and offer the safe way to get the same result. Never disable or skip a test to get green.

## Quality and security come first
We hold a high bar for code quality and security on every change, however small. Speed never justifies lowering either.
- **Secure by default.** Treat every input as untrusted, keep the rules below intact, and when unsure take the safer option and say why.
- **Fix at the root.** Fix a bug once in the shared component or helper, and check every caller, rather than patching each screen.
- **Leave it cleaner.** Reuse what exists, match the surrounding code, and delete code you make unused. No dead code or quick hacks without a `shortcut:` comment that names the limit.
- **Prove it.** Add a test for any new logic. `pnpm lint`, `pnpm typecheck` and `pnpm test` pass before every commit (Node 24). Never skip, loosen or delete a test to get green.
- **Accessible as built.** Real buttons and links, 44pt targets, 4.5:1 text, a 3:1 boundary on controls. Errors are sentences in danger with their icon (`ErrorText`).

## Non-negotiable rules (see `docs/security.md`)
- **Before changing any route, repository, migration, auth, upload or job code, read `docs/api-security.md` and finish with its checklist.**
- Every API route is built with `route()` from `@robes/api`, declares `auth`, a zod `input` and `output`, and `rateLimit`/`quota` if it spends money. Public routes must be in the route-manifest allow-list **and** `docs/api.md` §3.
- Identity comes only from the Better Auth session (`user.id`). Never read a user id, wardrobe, style DNA or entitlement from a request body — load it from the database.
- Anything slower than ~3 s or that calls a paid model is a job (`generation_jobs` + queue). No in-process state (Maps, timers) in the web tier.
- **The API is the only path to app data (ADR-019/020).** See "Data access and security" below — read it before touching `db/`, `packages/db`, `packages/auth` or a route.
- No `dangerouslySetInnerHTML`, no third-party script CDNs, no raw colours (use tokens), no hard-coded user-facing strings (use `@robes/copy`).
- No PII or prompts in logs. Provider/model errors never reach users.
- **Robes never deletes her data (owner, 12 Nov 2026).** A migration, backfill or fix adds or copies; it never truncates, drops, resets or overwrites what she has in staging or production. Bringing legacy beta accounts over merges into any account she already has. What she removes herself in the app (a piece, her account) is hers to remove.
- New personal data (column, table, bucket prefix, log/analytics field or processor) is added to `docs/data-inventory.md` in the same PR (SEC-85). Analytics and client error capture run only after her yes (native asks once after sign-in; the web's switch in You › Privacy starts off); replay loads only after her yes to Screen recordings (`recordings`) and to Share my looks with Robes (`look_sharing`), which covers recordings of her looks (SEC-84; Annie, 26 Nov 2026: no new consent kind, no re-asking), and shows the app as she sees it — her words, her photos, crops and her drawn model — so a tester's recording shows a render bug (Annie, 26 Nov 2026; supersedes "never a photo", 16 Nov), but never her email, the sign-in code, a password or another user's data — mark any new place one of those appears with `UNRECORDED` (web: the class from `@robes/analytics`; native: `components/Unrecorded`), and never put `UNRECORDED` on product UI (photos, pieces, the model, a look's words). An older `replay` yes never starts a recording; events come from the `@robes/analytics` catalogue.
- Model IDs only via the registry in `packages/ai`; prompts are versioned modules with evals.

## Data access and security (ADR-019/020) — read before changing data code

Postgres is a private database behind the API: no RLS, no client-side queries, no Supabase. Auth is Better Auth (`packages/auth`) running in the Next app. That model is only safe while every rule below holds — each exists because breaking it exposes every user's data or account.

**Database**
1. **App tables live in schema `app`.** Nothing but dbmate's `schema_migrations` lives in `public`. If the DB host ever auto-exposes a schema over HTTP (Supabase PostgREST, Neon Data API), it must be switched off — `meta.test.ts` guards `public`.
2. **PUBLIC gets nothing.** No table or function privileges for PUBLIC in `app`/`private`. Postgres grants EXECUTE on new functions to PUBLIC globally, and a per-schema revoke silently does nothing; the baseline revokes it globally, so every function grant is explicit. `security definer` functions must `set search_path = ''` and use fully-qualified names.
3. **The API and workers connect as `robes_app`** (`DATABASE_URL`), a login role with CRUD on `app` only. Migrations run as the admin role (`DATABASE_ADMIN_URL`, CI/deploy only). Never run the app as a superuser.
4. **Integrity lives in the database, ownership in code.** Every child table carries `user_id` and uses composite FKs (`(x_id, user_id) references parent (id, user_id)`) so a bug can never link one user's rows to another's. Keep check constraints, `private.track_updates` on every table with `updated_at`, and generated reference data (`@robes/core` → `pnpm --filter @robes/core gen:sql`, drift-tested).
5. **Migrations only via dbmate** (`pnpm db:new <name>`, files in `db/migrations`, forward-only — fix mistakes with a new migration, never edit an applied one). **Any database change follows `docs/runbooks/database-migrations.md`**: staging and production each migrate themselves in their Vercel build (`pnpm db:migrate` before `next build`; production as `robes_migrator`, which has no rights on legacy beta's tables in the same database), so every migration must work with the old code and old phone app versions still running (Releases and compatibility, below). New table checklist: schema `app`, `user_id` + composite FKs, `created_at`/`updated_at`/`deleted_at`, `track_updates`, schema tests in `packages/db/test/schema`, and repository functions (below). Then `pnpm db:types`.

**Code**
6. **All user-data queries go through `@robes/db` repositories whose first argument is a `UserId`** — a branded type only `verifiedUserId()` in the auth layer mints. Every query filters on it. Route handlers never build SQL or import Kysely. A missing row for this user is `not_found` (404), never `forbidden`. Every repository has a cross-user test. Worker-only operations live in `createSystemRepositories` and are never imported by routes.
7. **Admin = `app.admin_users.role = 'admin'`** (`support`/`analyst` are not admins). Admin routes use `auth: 'admin'` and write `app.audit_log`.
8. **Never return a DB row as-is.** `route()` parses every response with the `output` schema (zod strips undeclared fields) in every environment. Don't loosen outputs with `.passthrough()`/`z.any()`.
9. **Job progress is SSE from `/api/v1/jobs/:id/events`**, scoped by the session user like any other route. Don't add a client-side subscription to the database. Job handlers (`packages/jobs`) load all context from the DB by the job row's `user_id` (`ctx.userId`); job input carries ids and intent only (SEC-16).
9a. **User photos are private by default** and only ever delivered through signed URLs/cookies (`@robes/media/delivery`). Never make a bucket or prefix public except `shared/` (share snapshots) and `catalog/` (brand assets, no user data).

**Auth (Better Auth, `packages/auth`)**
10. Sessions are server-side rows (`app.sessions`); web uses httpOnly secure cookies, native uses the Expo plugin (SecureStore). Never store tokens in `localStorage`/AsyncStorage.
11. Sign-in is passwordless email OTP, plus Google on the web and Android; iOS is the email code alone (design "Sign in and sign up", 18 Nov; the server still runs Apple for existing accounts). Sign in and sign up are twin screens (web `app/auth/auth-form.tsx`, native `features/auth/AuthScreen.tsx`); sign up's optional first name saves only onto an account with none (`signUpFirstName`). OTPs are stored hashed, expire in 10 minutes and allow 3 attempts; Better Auth's rate limiter uses the database store (never memory in deployed envs).
12. `trustedOrigins` and OAuth redirect URLs are exact — no wildcards in production. `BETTER_AUTH_SECRET` is ≥32 random bytes per environment; rotating it logs everyone out (runbooks/key-rotation.md).
13. Account deletion goes through the deletion job (SEC-80), which deletes the `app.users` row last (everything cascades from it).

**API wrapper (`packages/api`) — hardening that review found missing; don't regress it**
15. Request bodies are streamed with a byte counter (32 KB cap). Don't call `req.json()`/`req.text()` yourself — a chunked request without `content-length` would bypass the cap.
16. Failed authentication is rate-limited per IP (`AUTH_FAILURE_LIMIT`) *before* returning 401; per-user limits never see bad-token floods.
14. Identity comes from the Better Auth session resolved server-side for each request (cookie or Expo header). Never decode or trust a token client-side, and never accept a user id from the body.
17. Client IP comes from `x-vercel-forwarded-for` → `x-forwarded-for` → `x-real-ip` via `app/src/server/client-ip.ts` only.
18. GET/HEAD/DELETE inputs come from the query string: values are strings (use `z.coerce`), repeated keys arrive as arrays. Route params are validated with the optional `params` schema.
19. The route-manifest test covers every `route.ts` under `app/src/app` and every HTTP method, and sends no token and a forged token. Keep it passing; don't narrow its glob.

**Web surface**
20. Pages render dynamically (root layout awaits `connection()`) so Next can stamp the per-request CSP nonce; a static page's scripts are blocked by `'strict-dynamic'`. The e2e suite fails on any CSP violation — add new third-party origins to `server/security-headers.ts` deliberately.
21. Env is parsed once at boot by `@robes/config` (server) and fails closed; don't add silent fallbacks to localhost/defaults in production code paths. `proxy.ts` does only the optimistic session-cookie redirect — real checks happen in pages and `route()`.
22. Native clients must use the same `cookiePrefix` as the server (`robes`) or Better Auth's Expo client silently drops the session.
23. Kysely's CamelCasePlugin maps **column names only** (`maintainNestedObjectKeys: true`): jsonb values come back exactly as written. Read calendar `date` columns as text (`worn_on::text`) — `pg` turns them into local-time `Date`s that shift across timezones.

**Secrets**
24. Nothing secret in the repo (gitleaks runs in CI on each change's commits). Publishable/anon keys are not secrets but still come from env. The legacy app has keys in its git history; they are being rotated and scrubbed after merge — never copy values from legacy files.

## Releases and compatibility (ADR-022) — read before changing a route, a schema in `packages/api-client`, or a migration

Installed iPhone builds run for months against today's API, and production, its workers and the app ship at different times. Each rule below exists because breaking it broke testers (0.7.0 failed on #259's wider Style DNA ranges, 25 Nov). The steps are `docs/runbooks/ios-release.md`; the words are the root `GLOSSARY.md` → Releases.
1. **Production serves every supported app version** (at or above the minimum app version). Within `/api/v1`, add and never take away: a new request field is optional, an input is never narrowed, a route is never renamed or removed, and a response field a supported app reads stays. `/api/v2` is not the escape hatch.
2. **A change a supported app can't handle is a two-step change, never one PR**: first production accepts old and new and the new app ships; later, by its own PR, the minimum app version rises to retire the old app (only once PostHog shows no sessions below it for 7 days, or those builds are past TestFlight's 90 days). Say which step a PR is in its description. **CI checks it**: each build's contract is saved as `packages/api-client/contracts/<version>.json`, and `compat.test.ts` fails a change that breaks any saved version at or above the minimum. Never edit a saved contract to make the test pass; delete one only when the minimum passes it.
3. **Responses are read tolerantly from 0.9.0 on; until the minimum app version reaches 0.9.0, a wider response is still a break.** `packages/api-client` mends a response or job event its build's schema rejects (`tolerant.ts`): a number out of range is clamped, a too-long string or list is cut, any other unreadable value becomes null, absent or its default as the schema allows, and a required one takes what holds it (a nullable or optional object, or its list item). So from 0.9.0 a new enum value or a wider range is safe, **except a new value in a required field outside any list** (nothing can stand in for it): make that field optional, nullable or `.catch()`ed first, or ship it as a two-step change. Before 0.9.0 the app rejected the whole response (#259 broke 0.7.0 this way).
4. **Migrations work with the code and the apps already running** (`docs/runbooks/database-migrations.md`): production migrates in its Vercel build, before the workers move.
5. **The sync carries `platform/` whole and only Niall merges it**: one PR into `main`, `sync/platform`, which `.github/workflows/platform-sync-pr.yml` rebuilds from `origin/beta` after every beta merge (`git rm -rq platform && git checkout origin/beta -- platform`, then `git diff --stat origin/beta HEAD -- platform` prints nothing). Never a whole-branch PR into `main`, a hand-picked path list, or an old sync branch; `.github/` changes go over by hand (the workflow token can't push workflows).
6. **Workers deploy after production has migrated**, from `main`, `Production/Workers` alone behind a `cdk diff` that shows only the functions' code (`infra/src/lib/diff-guard.ts`): `platform-deploy-prod-workers.yml` does it when Vercel reports robes-prod's build of a `main` commit succeeded and `main` hasn't changed `platform/` since (a failed or unfinished diff deploys nothing). Anything more than code stops there for a person; never `'Production/*'` from a laptop.
7. **iPhone builds are cut from `main` after the sync**, never from `beta`: every build talks to production, so production must already serve it. The app's `version` rises by PR into `beta`, and the build's contract is saved from the tree it was built from (`contract:save`).
8. **The minimum and latest app versions live in `app/src/server/app-versions.ts` and rise only after Apple has approved that build for the public beta**, each by its own PR into `beta` that reaches production with the sync. The app asks for them at launch (`GET /api/v1/public/app-versions`): below the latest it offers the update once per version; below the minimum every request answers 426 and the app shows only the update screen, whose one button opens TestFlight until the App Store release.

## Conventions
- **A toast never covers the tab bar.** On a tab root it stands above the bar (native `TabScreen` lifts it by the tab bar's inset while the tab is in view; web `AppShell` lifts it clear of the phone dock with `useToastLiftOver`), as a draft's footer lifts it above its own bar. A toast over a tab took the tap, and on an Undo toast undid what she had just done (16 Nov).
- **Global CSS goes in `@layer base`** (`app/src/app/globals.css`), so component utilities can override it; never `!` to beat a global rule. An unlayered `:focus-visible` once boxed every quiet field (28 Oct).
- **Weekday and month names come from the `@robes/core/calendar` tables**, never `Intl`/`toLocale*` (newer ICU prints "Sept"). `Intl` is only for reading a date in a timezone.
Match surrounding code; single quotes; 2-space indent; no comments unless the why is non-obvious. Tests live next to code (`*.test.ts`) except e2e (`app/e2e`, `mobile/e2e`) and DB tests (`packages/db/test`, need `pnpm services:up`).
