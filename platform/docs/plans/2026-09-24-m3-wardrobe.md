# M3 Wardrobe Implementation Plan

> Task-level plan; TDD per task. Backend tasks (1–4) run while the M2 UI packages are built; screens (5–8) land on `@robes/ui` / `@robes/ui-native` / `@robes/api-client`.

**Goal:** Getting a wardrobe in is fast and pleasant; one ingest pipeline; pieces look great.
**Inputs:** `roadmap.md` → M3; `reference/legacy-api-and-ai.md` §4.2 (analyse, read-url, receipts); `reference/legacy-features.md` §2 Wardrobe; `reference/ux-opportunities.md` D7–D9, UX-15/17–21; `security.md` SEC-20..22, 40, 41.
**Local-first:** everything runs on the docker stack; AI via `@robes/ai` (Gemini with `GEMINI_API_KEY`, deterministic fake without it).

## Backend
1. **Wardrobe repository** (`@robes/db` `wardrobeRepo`): list (cursor pagination by `created_at,id`, Refine filters: category/l2, season band, wear-for tag, source, hero first), get, create, update (editable fields only; season set by her flips `season_source` to `user`), soft delete + restore (UX-15), hero positions (≤10, unique), stats via `wardrobe_item_stats`. Cross-user tests for every method.
2. **Contracts + routes**: `GET/POST /wardrobe/items`, `GET/PATCH/DELETE /wardrobe/items/:id`, `POST /wardrobe/items/:id/restore`, `POST /wardrobe/items/batch` (N ready/pending asset ids → N `reading` pieces + one `wardrobe_analyse` job each, quota `analyse.photo`), all through `route()`; route map entries for the API client.
3. **Analyse job** (`wardrobe_analyse`): prompt module `packages/ai/src/prompts/wardrobe-analyse/v1.ts` ported from legacy (taxonomy block, fixed colour palette, formality, printed price/size only), schema-validated, `resolveTaxonomy` decides the category, confidence → auto-file (`status: ready`) vs Inbox; image loaded from the asset's master rendition by the worker (never from the request, SEC-16); ledger + breaker; fake fixture for offline dev.
4. **Inbox** (`wardrobe_inbox`): uncertain reads land here; `GET /inbox`, `POST /inbox/:id/decide` (file to wardrobe/wishlist or dismiss) — receipts (Resend-inbound → SES inbound per ADR-021) and link import (isolated fetcher, SEC-40) follow as tasks 9–10.

## Screens (web + native)
5. Wardrobe grid (Pieces · Wishlist · Inbox segments), hero pieces first, Refine sheet, skeletons, optimistic delete with Undo.
6. Add pieces: web drop zone / multi-select; native camera-roll multi-select + camera capture → direct upload → batch → pieces appear "reading" within 1 s and fill in as analyse jobs finish (SSE).
7. Piece page `/piece/[id]`: photo, details, edit, tags, worn count, delete/undo.
8. Wishlist + "I bought this" promote.

## Later in M3
9. Link import via isolated fetch worker (SEC-40 bypass table). 10. Receipts via SES inbound. 11. Cutouts (fal BiRefNet) behind a flag. 12. Tags management.

**Exit gates:** UX-17..20 on device (Maestro + Playwright); SEC-40 table green; ingest p95 auto-tag ≤ 8 s with Gemini; no base64 in any API body.
